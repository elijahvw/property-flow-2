# October 24, 2026 · Form layout and error recovery

This local PF-23 refinement follows the user's request to improve forms that read as a plain box of text. It does not establish production acceptance. Existing roles, API requests, version checks, explicit page-only drafts and uncertain-submission recovery remain the source of behavior.

## Observed layout

Rendered desktop and 390px mobile fixtures exposed two concrete problems in the current platform-owner workflows:

- The subscription editor put every primary field and all ten company exceptions in one vertical flow. Its mobile scroll surface measured 2,261px in an 826px dialog; normal plan changes required scanning optional controls and long explanations.
- The monthly plan editor rendered 44px checkboxes centered in full-width rows, separated from their labels and descriptions. Its ten choices extended far down the dialog.

The existing sticky save action worked and was preserved. A separate shared problem placed a rejected request's error after the long form; focus stayed away from the error.

## Changes

Native fieldsets with legends now receive a restrained shared section treatment. The subscription editor groups plan/billing fields, uses a two-column desktop layout and keeps required change history separate. Optional company feature exceptions use a native keyboard-accessible disclosure; existing exceptions open for review. Exception controls remain mounted, preserving their exact values in explicit drafts and FormData. Compact feature rows retain readable labels, descriptions and current access choices.

Monthly plans use a responsive two-column feature-choice grid with compact checkboxes beside their labels; mobile uses one column and a full row remains a click target. Pricing fields are grouped. Archived plan revisions remain visible but cannot be newly selected while unavailable; the already-assigned revision is retained.

The shared Form places a server error summary above the fields, focuses it after rejection and scrolls it below the sticky dialog heading. Native browser field validation remains unchanged; no error-to-field mapping is invented. Interrupted writes retain the exact attempted payload and disabled fields for retry. Closing, saved drafts, stale source versions and duplicate prevention keep their existing semantics.
