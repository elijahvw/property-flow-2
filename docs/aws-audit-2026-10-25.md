## Prepared optimization

The new ECR policy removes **only untagged image manifests older than 30 days**. It preserves every tagged image, including all Git-SHA deployment and rollback releases. Live inventory currently contains no eligible images, so this change has no immediate measured savings. Tagged history still grows. An age/count rule for tagged images would need an inventory of running tasks, retained task definitions and rollback policy first.

RDS source now prepares **seven-day automated backup retention and deletion protection**, with regressions to keep both explicit. These address verified live gaps but require a reviewed maintenance rollout: enabling backups from zero can interrupt service, and retention can add backup storage costs. A restore exercise and a non-null recovery window are acceptance gates. `skip_final_snapshot = true` remains a separate decommissioning follow-up.

`config/dev-power.json` classifies the ECR lifecycle policy as retained configuration with no compute to stop and records database retention/protection rationale. The application/scanner service and database power targets are unchanged. The RDS source no longer claims automatic Free Tier eligibility; account credits/eligibility require separate billing verification.

Before applying, use ECR lifecycle preview with the checked-in `infra/terraform/modules/ecr/image-lifecycle-policy.json`, inspect every affected digest and verify none is required by a running or retained task definition. Lifecycle evaluation is asynchronous. A tagged image remains protected only while it retains a tag; do not strip tags from required releases. Review a normal Terraform plan, run the power-plan guard and preserve the repository's deployment approval boundary. The policy is prepared locally and is not active in AWS.

## Existing controls preserved

- Start waits for RDS before restoring ECS; Stop drains ECS before stopping RDS. The scanner stops with its application task.
- Account/region validation and serialized deployment/power actions protect the known development target.
- Terraform plan validation rejects deletion/replacement of the retained database and unclassified resources.
- Migration deployment creates/verifies a restore point and retains five workflow-owned snapshots. Unrelated snapshots are not cleaned up by that workflow.
- ECS uses a pinned scanner image, loopback-only scanner access, deployment circuit breaker/rollback, readiness health checks and a 60-second deregistration delay.
- S3 frontend public access is blocked and CloudFront OAC restricts origin reads; authenticated API caching is disabled.
