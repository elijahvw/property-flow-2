# Backend production-readiness audit — October 21, 2026

This review starts from merged source `75d5342` and covers the API entry point, cookie/session and CSRF handling, company/property authorization helpers, legacy administration and resident assignment endpoints, money source/balance rules, new inspection/agreement/notification routes, private documents/scanning, billing worker, schema constraints, validation runners and operating contracts. It is a source review plus the local evidence below; it is not a penetration test, production load test or live-account acceptance. No hosted configuration, account, data, provider, migration or deployment was changed.

## Findings addressed locally

| Severity | Finding and user impact | Change and evidence |
| --- | --- | --- |
| High | Legacy administration/assignment `serial()` transactions reread authority without the actor/company row fences used by newer operational routes. A request could validate an older snapshot while an account/membership revocation or company suspension was in progress. The platform assignment target-company check also lacked a company fence. | `application.ts` now takes actor and company fences before rereading authority; `activeCompany()` fences the target company. Platform user reads and company member reads use the transaction authorization wrappers. Ten deterministic PostgreSQL overlap cases cover account/membership/company changes, member edits, assignments and member-list reads. |
| Medium | Company-member PATCH treated `expectedVersion` as optional. An API caller could omit the version and overwrite a newer access decision despite the UI supplying a reviewed version. | Missing and stale versions now return `STALE_MEMBERSHIP` before access/audit changes. The existing UI contract is unchanged. Disposable users tests cover absent, null and stale versions and unchanged state/history. |
| Medium | Malformed JSON and unsupported media types fell through to HTTP503, presenting caller errors as service outages and polluting failure signals. Generic 413/429 messages always referred to 5MB uploads/sign-in, even for other requests. | Shared production error handler preserves framework 4xx status, keeps parser/driver/private text out of responses, uses request-appropriate wording and reports only server failures. Real Fastify injection tests exercise malformed JSON, unsupported content type, body limits, throttling/retry headers, access errors and private internal errors. |

Actor write fences deliberately serialize consequential requests by the same actor. Different actors retain shared company read fences. Serialization/deadlock retry remains bounded; failed attempts rerun authorization and retain the existing durable submission keys. Existing target-identity race tests now intercept only their intended target row, preserving real PostgreSQL behavior after adding the actor fence.

## Controls retained and reviewed

- Auth0 issuer/subject is the identity authority; email does not silently link accounts. Cookies remain HttpOnly, host-only and secure for HTTPS, with absolute/idle expiry and server-side token hashes. Mutations require exact Origin and session CSRF. Current account/membership/company state is read on requests and again for consequential transactions.
- Company property operations use transaction-local PostgreSQL context, explicit company filters, forced RLS and composite source foreign keys. Platform authority does not grant company financial authority. Staff scope/assignment and leaseholder-versus-occupant financial access remain separate.
- Financial amounts use exact cents/bigint totals over complete matching sources. Immutable cash/charge/allocation sources, versioned corrections, durable UUID/fingerprint replay, lease write fences and atomic audit remain in place. Oversized views fail explicitly instead of returning partial balances. This is current operational/cash tracking; full historical as-of accounting is still a separate capability.
- Inspections keep immutable review revisions and exact cleared evidence versions. Agreement preparation remains unsigned, checks actual recorded parties and detects changed source snapshots. Inbox counts, opens and retries recheck current source/company/user/property authority. No external delivery or electronic-signature capability is implied.
- Private originals stay behind source authorization and quarantine until a valid scanner verdict. File type/content/size, source/company retained storage and version counts are bounded. Daemon scanning stays on loopback, has concurrency/time limits and rejects stale definitions. Audit originals/source identifiers remain retained.
- Recurring billing coordinates replicas through lease fences and durable occurrences, records bounded failures, and does not invent payments or automatically charge fees. Telemetry filters private text/SQL/URLs, uses bounded queues and does not block business requests.

## Production gates and follow-on work

1. **Dependency remediation and continuing review:** the initial October21 production audit in this review reported 18 affected packages (10 high, 8 moderate, zero critical); a separate full baseline snapshot recorded22. The final updated source aligns Prisma CLI/client/adapter at7.10.1, React Router at7.18.4, Vite at8.3.4 and its React plugin at5.2.0, and replaces the affected development watcher chain with `tsx`. All four final root/server lock audits (full and production scope) report **zero known vulnerabilities**. See the [dependency audit](dependency-audit-2026-10-21.md) for versions, advisory context and toolchain compatibility. Prisma tooling's former Hono/MySQL chains were not evidence of a deployed Fastify HTTP exploit. Keep validated internal return-path handling, repeat dependency scans and validate builds/browser workflows after updates; a dated clean advisory scan does not prove the absence of application defects.
2. **Release/identity acceptance:** execute the existing owner/manager/staff/leaseholder/occupant and second-company checklist on the matching reviewed release. Test real Auth0 sign-in, verification/setup mail, invitation replacement/revocation and recovery. Fixture providers cannot establish external delivery. Domain/provider activation and Stripe remain separately approved work.
3. **Transport and deployment credentials:** the development contract documents HTTP between CloudFront and ALB and migration-owner credentials in the startup container. Production needs encrypted origin transport or an equivalent encrypted private path, plus a separately scoped migration job/task before removing migration credentials from the serving container. These require reviewed infrastructure work and Start/Stop inventory preservation.
4. **Recovery and operating ownership:** prove a restore into an isolated target, choose recovery objectives and record controlled incident/alert-delivery acceptance. Existing backup settings, successful deployment telemetry and paused/provisioned alerts do not prove recovery or an operator response. Use the monitoring coverage and release runbooks.
5. **Portfolio scale:** property/company/member selection paths still load complete directories, while operational views impose explicit source caps. Move growing directories to server search/keyset pages and preserve totals/filter/source semantics; measure representative portfolio load with concurrent role-safe workflows before claiming capacity. Keep complete financial views explicit while adding scalable aggregation; do not silently lift caps.
6. **Document lifecycle and accounting:** larger private object storage, explicit sharing/resident uploads, retained-data export/deletion policy and storage operations remain separate from the current management library. Opening-balance imports, historical as-of reporting, bank/provider reconciliation and period controls require complete financial contracts before payment collection.
