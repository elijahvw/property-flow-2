# Lease inspections — PF-16

The management inspection foundation is merged. The current local PR64/68 reconciliation applies the shared available-file policy after scanner retirement057; combined validation and deployment remain pending. The October 20 implementation/migration038 and regression statements below describe that earlier checkpoint. [Current reconciliation](pr64-pr68-reconciliation-2026-10-25.md).

Owners and managers open a lease → Inspections to record move-in or move-out condition. Each report has an inspection date and 1–100 named area/item observations with Good, Fair, Damaged, Not applicable or Not checked condition, bounded notes and up to 10 exact evidence versions per item. Area/item pairs are unique after whitespace and case normalization, which makes comparison unambiguous. Observations are separate from charges and deposit decisions.

## Complete workflow

Save observations → In progress → Submit for review → Awaiting review → Review completion with a note → Completed. Every item must be checked and damage described before submission. Review acts on the saved report’s opening version; it cannot replace its observations. Reopen an awaiting or completed report with a reason before correcting it. Reopening retains all previous completion reviews and originals. Management may prepare and review a report; this increment does not impose a separate-reviewer identity rule or claim a resident signature.

Each create, save, submit, complete or reopen retains an immutable revision with actor, date, reason where applicable, full observations and exact evidence identities. Consequential actions require a frozen opening version and durable submission key. Lost-response retries recover one committed revision and audit; altered replay payloads and stale changes fail explicitly. Every revision, evidence link and audit writes atomically; an audit failure rolls back the business change. History pages contain 25 revisions with explicit older/latest navigation. A lease retains up to 200 reports; exceeding retention fails explicitly instead of hiding records.

Unsaved inputs are retained only inside an open editor or after explicit Save draft & close on the current page. Add/remove item actions also trigger the closing warning. Discard removes that editor; navigation away or refresh clears an unsubmitted draft. A possibly committed request is frozen and kept separately for retry recovery while this page stays open. Nothing writes private observations to browser storage. Forms preserve input on validation and network errors; fresh access failure clears inaccessible report content.

## Evidence and comparison

Upload originals through the same lease's Documents workflow before linking them. Inspection links never copy files or invent a malware verdict. Only exact retained versions from this lease/company in the shared `unscanned`, historical `pending` or historical `clean` allowlist are accepted; rejected and unknown states stay blocked. New/legacy pending files display **Not scanned**, and historical clean verdicts retain their recorded status. Archiving or uploading a newer unavailable version does not replace earlier linked evidence; existing archive/history semantics remain unchanged. Evidence links open the actual source's retained versions in another tab, preserving the report/editor. Each download rechecks current source/version authority and availability through the document endpoint.

A move-out report can select an exact completed move-in revision from the same lease, dated on or before its move-out inspection. The directory offers the latest retained completion of each move-in report. An existing report keeps its previously selected revision even after a newer completion appears. Comparisons match normalized area/item names, show before/after condition and original notes/evidence, and explicitly show unmatched items on either side. Renaming an item is an unmatched observation, not inferred equivalence. A missing move-in report remains explicit rather than inventing a comparison.

Completed move-out reports link to the existing settlement workspace. The selected inspection survives lease section changes and reauthentication; settlement displays its fresh status/version and a return link. Reopened reports lose their completed status immediately. No inspection action creates a charge, deposit application, refund or ledger entry. Financial decisions remain separately reviewed in existing workflows. Automatic charge derivation and a new persisted financial-source relationship are outside this increment.

## Access, operations and validation

Every list, report, history, write and replay requires fresh `lease.manage`, active company membership and exact lease/company scope under the existing authorization fence and forced RLS. Platform authority, resident/occupant status and staff maintenance execution grant no inspection authority. Composite foreign keys bind revisions/baselines to their lease and evidence to its company; runtime cannot update or delete immutable history. Residents/staff do not receive these management-only observations or private originals.

Bounded `inspection.save` and `inspection.review` browser outcomes/durations complement existing API route metrics. No observations, filenames, source IDs, user names or query values are added to telemetry. For 409, retain the draft, inspect refreshed history and deliberately discard/reopen before changing the submission. For 403/404, check current management membership and exact source scope; do not broaden resident/staff grants. Correct invalid evidence at its real lease source; rejected/unknown originals stay blocked and historical verdicts are never manually relabeled. Audit failure must leave report/version/history unchanged before retrying the original key.

Original local regression coverage included migration/RLS and composite keys, roles/CSRF/source boundaries, the then-current quarantine/retention behavior, immutable reviewed baselines, concurrent replay, stale writes, audit rollback, complete history paging, fresh revocation/suspension, unchanged financial counts, real browser review/reopen, committed-response recovery, explicit drafts, exact-original navigation and phone layout. New retirement/available-file acceptance is tracked separately in the reconciliation record. Hosted rollout, real-account acceptance, resident acknowledgement/sharing, signed reports, templates and provider integrations remain separate work. There is no new inspection runtime service; preserve Start/Stop controls.
